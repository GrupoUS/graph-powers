# Skill Improver Dimension Rubrics

Load only the dimensions in scope. Every criterion is **default-FAIL**: it starts
`false` and only flips after the evidence file was opened with Read and cited as
`path:line`. No citation, no pass.

Severity: `P0` blocks the audit · `P1` needs a patch before the next release of the
harness · `P2` documented debt · `P3` note only.

## D — Discovery and schema

- **D1** Every `agents/*.md` and `skills/**/SKILL.md` parses and its `name` matches the
  file/folder. A basename mismatch is **not** a defect when the deviation is documented
  and covered by `config.json::agentRouting.aliases` — check before flagging
  (`explorer.md` → `name: explorer` is the attested case). P1 when undocumented.
- **D1b** An agent's `name:` is **unquoted** and lands inside the **first 600 bytes** of the
  file. a routing-guard hook (when the user has one) matches `^name:\s*([\w:.-]+)\s*$` against
  `read_text(...)[:600]` to build `KNOWN_AGENTS`; a quoted name or one pushed past 600 bytes
  by a long preceding field makes the guard treat the agent as unknown. **P0** — the spawn
  is rejected before the agent ever runs. Verify by byte offset, not by line number.
- **D2** `description` + `when_to_use` combined stay under **1.536 characters**, main use
  case first. Measure in characters with `python3`, not by eye. P2 when over.
- **D3** `.claude/loop.md` exists and is under **25.000 bytes**. P2 when absent — the
  harness simply has no bare-`/loop` prompt.
- **D3b** Every `.claude/agent-memory/*/MEMORY.md` is under 200 lines **and** 25KB. Also
  check the inverse defect: a directory with dozens of notes and **no** `MEMORY.md` means
  nothing is injected. P2.
- **D4** No duplicated `name` across agents, skills, commands and plugins. Precedence is
  enterprise > personal > project, so a `~/.claude/skills/<n>` **wins** over
  `${CLAUDE_PLUGIN_ROOT}/skills/<n>`. **P0** when the losing file is the authority for this repo — read
  both descriptions and say which one the listing actually serves.

## W — Wiring

- **W1** The call graph is built: command → skill → subagent → hook → script, every edge
  with `path:line` on both ends.
- **W2** Zero dangling references. A name cited in `subagent_type`, `Skill()`,
  `skills:` preload, `$1`/`$ARGUMENTS`, or a skill body resolves to a file that exists.
  Before confirming, rule out all four silent resolvers: **precedence** (a bare name may
  resolve to a personal skill), **aliases** (`config.json::agentRouting.aliases`),
  **module import** (a `hooks/*.py` not in `settings.json` may be imported by one that
  is), and **symlink** (`${CLAUDE_PLUGIN_ROOT}/skills/*` may be a link into `.agents/skills/`).
  A reference is also dangling when the target exists but the citing agent lacks the tool
  to open it. Severity by call site: **P0** when a command or workflow *executes* it,
  P1 when a live instruction reads it, P3 when it only appears inside an illustrative
  code fence.
- **W2b** A plugin-qualified `Skill("plugin:skill")` resolves only when the plugin is
  **enabled**. Check `enabledPlugins` in every settings layer (local overrides project
  overrides user) — an installed-but-disabled plugin is dangling at runtime. **P0** when
  a command declares the skill mandatory.
- **W2c** **Mirrors of a changed unit.** This harness keeps tracked copies of `.claude/`
  content for other IDEs — `.kilo/skills/` (28 skills) and `.agents/skills/` (40+). Changing
  a file under `${CLAUDE_PLUGIN_ROOT}/skills/*/scripts/` without updating its mirror creates a silent
  fork: the mirror keeps serving the old behavior to whoever runs from that directory.
  Executable check for any changed unit:
  `find . -name "<basename>" -not -path './node_modules/*' -not -path './.git/*'`
  then `diff` each hit against the pre-change version to tell "already divergent" from
  "this change caused the divergence". Attested 2026-08-17: fixing the `KeyError` in
  `${CLAUDE_PLUGIN_ROOT}/skills/skill-improve/scripts/run_evals.py` (then under
  `skills/skill-creator/`) left a `.kilo/` mirror byte-identical to the buggy original —
  it still raises `KeyError('assertions')`. P1 when the mirror is tracked by git, P2 when
  it is generated by a script (then the finding is "re-run the generator"). Grep for a sync
  script before assuming either.
- **W3** Zero orphans: every agent/skill/command is reached by at least one edge or by
  documented direct invocation. An orphan is a **candidate for documentation**, never for
  deletion — deletion needs double evidence and the user's decision. P2. Raise to P1 when
  the orphan owns a live business domain (billing, payments, messaging) and therefore
  never loads when it should.
- **W4** *(retired — premise refuted 2026-08-17)* `allowed-tools` in a SKILL.md is an
  additive pre-approval grant, not a restrictive allowlist: "it does not restrict which
  tools are available". Its absence never blocks a subagent spawn. Do not report it.
- **W5** Every hook declared in any `settings.json` points at an existing file with a
  shebang, and every hook on disk is either declared **or imported by a declared one**.
  The executable bit is irrelevant when the hook is invoked as `python3 <path>`. P1.
- **W6** No unintentional cycle (skill A → agent B → skill A). A cycle broken by an
  explicit refusal comment, a name/precedence split, or a `maxTurns`/round cap is
  intentional — say so and move on. **P0** only for a cycle with no brake, especially an
  evaluator that carries the `Agent` tool and can spawn a write-capable agent
  (permission laundering).

## L — Loop-engineering compliance

- **L1** Every agent that evaluates, reviews, or researches declares `tools:` allowlist
  without Write/Edit **or** `disallowedTools: Write, Edit`. Both forms are canonical. A
  subagent with **neither** field inherits Write/Edit regardless of what its prose
  promises — that is **P0**, and the prose makes it worse, not better, because it reads
  as a guarantee.
- **L1b** An allowlist without Write/Edit is **not sufficient when the agent also declares
  `memory:`** — that field grants `Read`, `Write`, `Edit` on top of the allowlist.
  **Executable check** (you have Grep, not the resolved registry):
  `grep -rn '^memory:' .claude/agents/*.md` — a hit on an agent whose `role_type` is
  `evaluator` or `researcher`, or whose description claims read-only, is **P0** with no
  further proof required. The resolved tool set is only observable when the caller pastes
  it into your prompt; when it is absent, say so and rule on the grep. Attested:
  `agents/librarian.md:4` (9 tools, no `Read`) + `:10` `memory: project` resolves with
  `Write, Edit, Read` added, against its own "Never inspects or edits local files".
  Two candidate fixes — drop `memory:` (removes the grant at its source, verified by the
  4 memory-less agents resolving to exactly their allowlist) or add
  `disallowedTools: Write, Edit` (documented as applying first, **not measured against
  this grant** — flag that gap rather than asserting it works). Never "add the missing Read".
- **L1c** No agent carries an allowlist that prevents it from executing its own body
  (e.g. a body that says "Read X" on an agent whose allowlist omits `Read`). Check L1b
  first: `memory:` may already have supplied the tool, which turns an apparent capability
  gap into a hidden write path — the opposite defect and a worse one. P1.
- **L2** A handoff artifact exists on disk (`PROGRESS.md` or equivalent) and `CLAUDE.md`
  orders reading it first. Check whether anything already *cites* such a file — readers
  waiting on a producer that does not exist is the common shape. P1.
- **L3** Explicit brakes: an iteration/wave cap in every workflow, a turn clause, and an
  `AGENT_STOP` kill-switch. Count them; "one of three" is a fail with a partial note. P1.
- **L4** Multi-agent councils anonymise the reports (A/B/C/D, shuffled) before cross
  review. Grep for anonymise/shuffle/blind. Unanonymised council = each model prefers its
  own answer. P2, P1 on the most expensive review flow in the harness.
- **L5** Guardrails: isolation (`isolation: "worktree"`/container), credentials out of the
  sandbox's reach (`permissions.deny` on env/secrets), **and** an explicit token/cost cap.
  Also check that parallel write-capable agents have *mechanically* disjoint file sets —
  a classifier agent's JSON is not proof. P1.
- **L6** Evidence of pruning: `git log --diff-filter=D -- .claude/`. A harness that only
  grows carries expired assumptions. When pruning happened, check the follow-through — a
  deleted command that is still cited is a W2 finding, not an L6 pass.

## E — Evidence and eval

- **E1** High-use skills have `evals/evals.json`, and a with-skill vs without-skill
  baseline exists on disk. Run the repo's own runner before trusting the file: a schema
  the runner cannot read is worse than no eval, because it reports success over zero
  cases. P1.
- **E2** A `learning.md` per high-use skill in the shape
  **hypothesis -> change -> measurement -> verdict**. An entry with no measured number is not
  a learning loop. P2.
- **E3** The harness's own validators accept valid input. Run them and read the failure:
  a gate that rejects correct files (for instance flagging `description: >-`, valid YAML
  block scalar, as an illegal angle bracket) trains everyone to ignore the gate. P1.

## Limits of this rubric (state them when they bite)

- **`tools:` allowlist without Write/Edit is not a sandbox.** Any agent that also has
  `Bash` can write via `>`, `tee`, `sed -i`, or `python3 -c`. When you rule an agent
  read-only on the strength of its allowlist, say "no Write/Edit tool; Bash remains a
  write vector governed by its Iron Laws" — never "cannot write". Same for L1: the fix
  reduces the surface, it does not seal it.
- **You cannot observe the resolved tool set**, only the frontmatter (see L1b). Rule on
  the grep and label the confidence accordingly.
- **`~/.claude/**` is outside the repo's control.** A finding there (a `SubagentStart`
  matcher that omits an agent, a hook not declared, a global skill shadowing a project
  one) cannot be fixed by a repo commit. Report it as `ESCOPO GLOBAL — fora do repo` with
  the exact edit the user must make by hand, and never count it against the repo's verdict.

## S — Security and config

- **S1** No plaintext secret anywhere in the harness, repo or global. Report `path:line`
  and the kind, **masked**. **P0**, always.
- **S2** No credential-bearing file world-readable (`0644`). Watch for `[conflicted]` /
  `[copy]` duplicates of a `0600` original — sync tools recreate them with default perms.
  **P0**.
- **S3** No stale absolute path from another operating system in a live config — a Windows drive letter or a home directory from someone else's machine.
  Silently disables whatever it points at. P1.
- **C1** No contradiction between `settings.json`, `settings.local.json` and a plugin
  registry over the same key. Local overrides project overrides user — name the winner. P1.
- **C2** Every `skillOverrides` entry that disables an artifact is documented. An
  undocumented `off` looks exactly like a wiring bug and burns an audit cycle. P2.
- **C3** Per-command context cost stays reasonable. A command file over ~20KB is injected
  whole on invoke; over ~40KB it competes with the actual work for the window. P2.

## Cross-dimension filters

Drop any finding that lacks both a violated contract and a plausible failure mode.
When two findings share a root cause, report the cause once and list the call sites.
Never report a defect in production code (`apps/**`, `packages/**`, `scripts/**`) —
that scope belongs to `/pr-review` and `evaluator` Mode 4. Out of scope, say so and stop.

## Known auditor failure patterns (check yourself against these)

Each of these produced a false P0 in the 2026-08-17 baseline audit:

1. **Hook on disk not in settings = dead code.** Wrong twice. `~/.claude/hooks/protect_files.py`
   and `plan_validator.py` are imported as modules by `pre_write_guard.py:27-33`, which *is*
   declared. Grep for importers before calling a hook orphaned.
2. **`skills:` count mismatch = missing SKILL.md.** A `plugin-root/skills/adhd` path can be a symlink into
   `.agents/skills/`; `find` does not follow it but `[ -f ]` does. Check for symlinks.
3. **Bare agent name in a code fence = dangling `subagent_type`.** Role labels defined in an
   earlier fence (`commands/debug.md:124-146`) are documentation, not spawns. Grep for the
   actual `subagent_type:` before flagging.
4. **Skill orchestrates without `allowed-tools` = cannot spawn.** Refuted premise; see W4.
5. **Read-only agent that says so in prose = compliant.** The prose is the *symptom*; the
   missing `tools:` field is the defect. See L1.
6. **Every read-only agent belongs in `MUST_BACKGROUND`.** The attested split is narrower:
   read-only *researchers* (`explorer`, `librarian`) go background; read-only *evaluators*
   (`evaluator`, `security-reviewer`, `skill-improver`) stay foreground because a caller
   gates its next phase on the verdict. a routing-guard hook (when the user has one) lists
   only the researchers, and the comment on :125 records that `evaluator` was deliberately
   excluded. Do not flag an evaluator's absence from that set.
