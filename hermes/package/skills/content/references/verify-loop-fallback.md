# Verify-loop fallback

> Conditional fallback for `/verify loop` when `ultra-verify` is unavailable, unresolved or declines.

Run `/verify` §§ 0–3 and § 1.5's applicable independent batch: evaluator always,
security-reviewer for auth/API/schema, web or user input, and ui-ux-designer for web. The fresh read-only evaluator
reviews the plan, current snapshot/package, task ledger, acceptance checklist and Gauntlet coverage;
author inspection is insufficient.

Critical or Important findings return only to their existing owning write lane for material correction,
focused re-gate and fresh independent confirmation. Use only `chain.maxFixRounds`; never create an
extra final round. An exhausted or unavailable writer/reviewer returns `NEEDS-WORK` or `BLOCKED` with
the lease and evidence explicit. Do not retry workflow resolution.
